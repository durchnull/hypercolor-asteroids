# Referee

```sh
tools/golden-check.sh            # working tree, advisory, never blocks
tools/golden-check.sh --staged   # what the hooks will see
```

The full text of every rule is in [GOLDEN_RULES.md](../../../GOLDEN_RULES.md).
Read the rule before you explain it — quote the reason, not the number.

## Red lines: GR1, GR2, GR7, GR10, GR11, GR12, GR13

Not overridable, by anyone, including the person who wrote them. Fix the cause:

- **GR1** — something does not parse, an import points at a file that is not
  there, or `index.html` loads something that does not ship. Usually a file
  that was never created or never staged. Check `git status` for untracked
  modules.
- **GR2** — a dependency, a build step, or something reaching for the network.
  Whatever it was for, do it with the platform. This game plays from a USB
  stick in ten years.
- **GR7** — an `@author` tag, or `git config user.name` is not set. Names live
  in the history, not in the source.
- **GR10** — rules and game code moving together. Split the commit: `git reset`
  the referee files, land the game change, then land the rule change on its own
  with a `Rule-Change: <why>` line.
- **GR11** — somebody else's event file, an event signed with a name that is not
  yours, or the guard in the runner no longer recognisable. Write your own file
  under your own name instead.
- **GR12** — `src/game/ledger.js` does not match the history. Run
  `tools/tally.sh` and let it write the file; if that still disagrees, something
  is editing a count by hand and the answer is never to help it along.
- **GR13** — somebody who did not open this repository is changing the orb or
  its song: the heredoc in `tools/chronicle.sh` that writes
  `docs/chronicle-song.js`, or that file hand-edited away from it. Revert that
  part, keep the rest, and take the idea to the owner —
  `git log --max-parents=0 --format='%an'` says who that is. There is no
  override, and moving the work to another file does not move the line.

If somebody genuinely needs a red line changed, that is legitimate — it just
happens in the open, as its own commit, where the others can see it and argue.

## The tally: GR12

Every override, and every commit the referee never got to see, is counted per
pilot in `src/game/ledger.js` — generated by `tools/tally.sh` off the history,
committed by the hooks the moment it happens, and checked against the history
at commit time. A bend is worth one, going round the referee is worth two.

```sh
tools/tally.sh --roll     # the standings, and what each number costs in the field
```

What it costs is in the game rather than on paper: events come sooner, and at
three bends a pilot's own events stop sparing them (the one exception GR11
carries). Mention that once when somebody is about to spend a budget — before
they spend it, not after — and then get out of the way. It is a difficulty
setting they chose, not a telling-off.

Never edit the ledger, never run the tool to make a number smaller, and do not
help anybody else do it either. It is derived; that is the only reason it is
worth anything.

## Budgets: GR4, GR5, GR6, GR14

You are allowed through. The question is only whether it is fair, and the user
decides that, not you.

Put it to them concretely — whose file, how many lines, what breaks for them:

> `src/features/kraken.js` is Mira's and this removes 40 net lines from it. That
> is GR4. I can write the override, or I can do this additively instead — the
> dive state could take a flag rather than being replaced.

Offer the additive alternative first, because it is usually better code as well
as better manners. If they still want it, write the line and land it:

```
Golden-Rule-Override: GR4 - the dive state was unreachable after the portal
                            change; rewritten with Mira's agreement
```

One round of discussion, then their call. Do not relitigate.

GR14 is the one budget with a cheaper way out than the override line, so offer
that first: the block means three versions have landed since this pilot last
flew, and four minutes at the keyboard clears it for the next three.

```sh
tools/flights.sh --count "$(git config user.name)"    # how far past the meter
tools/flights.sh --roll                               # the whole room
```

Say it as an invitation rather than a fine — *play it and paste me the tape*.
If they would rather land now and fly later, that is a legitimate call and the
line is `Golden-Rule-Override: GR14 - <why>`; it costs one on the tally like
any other bend. Do not ask twice, and never suggest a token flight to clear a
number: a tape that was not a flight is worse than the override, because the
override is at least honest.

## Nudges: GR3, GR9

Mention them once. A feature outside `src/features/`, a missing `guide` entry,
a README edit that spoils the surprise. None of it blocks anything.

## Never

Disabling the check is not a fix. `--no-verify`, unsetting `core.hooksPath`,
editing `tools/golden-check.sh` to make a failing commit pass, or moving a file
to dodge an ownership check — refuse all of it in one sentence and offer the
override instead.
